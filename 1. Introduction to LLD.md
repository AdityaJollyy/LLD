# Low-Level Design (LLD)

<details>
<summary><strong>📌 1. Introduction to LLD</strong></summary>

## Understanding LLD

A simple way to understand **Low-Level Design (LLD)** is to compare software development with building a house:

* **High-Level Design (HLD)** is like an **architect's blueprint**. It describes:

  * Where the rooms will be.
  * How large they will be.
  * How the rooms are connected.

* **Low-Level Design (LLD)** is like deciding the **detailed implementation** of the house:

  * Where switches should be placed.
  * How the plumbing should be laid out.
  * What materials should be used.
  * Other detailed decisions required before construction.

Therefore, **LLD focuses on the small, detailed planning required before actually building the system or writing the code.**

</details>

<details>
<summary><strong>📖 2. Definition of Low-Level Design</strong></summary>

**Low-Level Design (LLD)** is a phase of the **Software Development Life Cycle (SDLC)** that focuses on the **detailed design of individual components or modules** of a software system.

It specifies:

* The **internal structure** of components.
* The **algorithms** that will be used.
* The **data structures** required.
* How individual components will implement the system's functionality.

LLD acts as a **bridge between High-Level Design (HLD) and actual coding**.

### In Simple Terms

> **HLD tells us what the system looks like at a high level, while LLD explains how individual components will actually be implemented.**

</details>

<details>
<summary><strong>💻 3. Coding Example</strong></summary>

Consider a basic **Login System** for a website.

At the LLD level, we would identify and design specific components/functions such as:

* `login()`
* `signUp()`
* `forgotPassword()`

LLD would define the **functionality and detailed behavior** of these components rather than simply stating that the system needs "user authentication."

</details>

<details>
<summary><strong>🔍 4. Key Characteristics of LLD</strong></summary>

### 4.1 Granular and Code-Level

LLD goes deep into the **fine details of how each component will function**.

It defines elements such as:

* **Classes**
* **Functions**
* **Variables**
* **Data structures**

For example, instead of simply stating:

> "The system needs user authentication."

LLD specifies:

* Which classes will handle authentication.
* Which methods will validate login credentials.
* What should happen when authentication fails.

Thus, LLD brings the design much closer to the actual code.

---

### 4.2 Implementation-Focused

LLD is directly connected to **how the actual code will be written**.

It acts as a **blueprint for developers**, providing guidance about:

* The logic of modules.
* The flow of operations.
* The structure of components.

LLD may include:

* **Pseudocode**
* **Flow diagrams**
* **Sequence diagrams**

These can illustrate the **real-time flow of data between functions**.

---

### 4.3 Applies OOP Principles

LLD makes extensive use of **Object-Oriented Programming (OOP)** concepts, including:

* **Classes**
* **Inheritance**
* **Abstraction**
* **Encapsulation**
* **Polymorphism**

Using these principles helps create systems that are:

* **Modular**
* **Reusable**
* **Maintainable**

#### Example

A system can have a base:

```text
Notification
```

class with subclasses such as:

```text
EmailNotification
SMSNotification
```

The subclasses can use **inheritance and polymorphism** to provide different notification implementations.

</details>

<details>
<summary><strong>👥 5. Stakeholders in LLD</strong></summary>

The stakeholders involved in **Low-Level Design** are primarily the people directly involved in the **implementation of the system**.

These include:

* **Senior Software Developers**
* **Technical Leads**
* **Managers**
* Other people directly involved in implementing the system

LLD is therefore mainly concerned with providing an implementation-level design that these stakeholders can use while developing the system.

</details>

<details>
<summary><strong>⚖️ 6. HLD vs LLD</strong></summary>

| **Aspect**          | **High-Level Design (HLD)**           | **Low-Level Design (LLD)**                   |
| ------------------- | ------------------------------------- | -------------------------------------------- |
| **Purpose**         | System overview and modules           | Detailed implementation and logic            |
| **Level of Detail** | Abstract                              | Highly detailed                              |
| **Focus**           | Architecture, modules, and interfaces | Classes, methods, and implementation details |
| **Outcome**         | Modules and system diagrams           | Detailed class and method diagrams           |

### Quick Difference

**HLD → Overall system structure**

**LLD → Detailed implementation of individual components**

</details>

<details>
<summary><strong>⭐ 7. Importance of Low-Level Design</strong></summary>

LLD plays an important role in the **Software Development Life Cycle** and is particularly relevant to software development roles involving detailed implementation.

### 7.1 Avoids Rework

Clearly defining the **logic and structure** of the system helps identify design issues early.

This reduces the possibility of making **costly changes later during development**.

---

### 7.2 Improves Collaboration

LLD provides a **shared reference** for the development team.

It helps team members understand:

* Component behavior.
* How different components interact.
* Integration points between components.

This creates a common understanding of how the system should be implemented.

---

### 7.3 Promotes Scalability

Well-designed and **modular components** can accommodate:

* System growth.
* New features.

This can be achieved without requiring a **major redesign** of the existing system.

---

### 7.4 Encourages Best Practices

LLD encourages the use of:

* **Clean code**
* **Design patterns**
* **OOP principles**

Following these practices contributes to software that is:

* **Maintainable**
* **Robust**

</details>

<summary><strong>🎯 Interview Quick Revision</strong></summary>

### What is LLD?

**LLD is the detailed design phase of software development that defines the internal structure, algorithms, data structures, classes, methods, and other implementation details of individual system components.**

### HLD vs LLD in one line

> **HLD defines the overall system architecture, while LLD defines the detailed implementation of its individual components.**

### Key Characteristics

**LLD = Granular + Implementation-focused + OOP-oriented**

### Why is LLD important?

1. **Avoids rework** by identifying design issues early.
2. **Improves collaboration** by providing a shared implementation reference.
3. **Promotes scalability** through modular components.
4. **Encourages best practices** such as clean code, design patterns, and OOP.
